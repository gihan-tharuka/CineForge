- (decision) AD-0: Design paradigm = Clean/Hexagonal Architecture (Domain, Application, Infrastructure, Presentation layers). Chosen over Vertical Slices because two different surfaces (admin API + public redirect) share the same domain logic.
- (decision) AD-1: Single .NET project with two controller groups (Admin API + Redirect Service) in v1. Separate deployments deferred until scaling demands it.
- (decision) AD-2: Interstitial page served by .NET backend (Razor view or static HTML), not by the React SPA. Keeps the redirect lightweight — no React bundle download for scanners.
- (decision) AD-3: Data model — CurrentRedirectUrl stored as a column on the Campaign table. UrlChangeLog table for audit trail. Simpler query for the redirect path.
- (decision) AD-4: API design = RESTful Controllers (not Minimal APIs). Route structure confirmed. Clean Controller-per-resource pattern aligns with TanStack Query.
- (decision) AD-5: Scan recording = inline async write (fire-and-forget). Simplest approach for v1. Background queue deferred if scan volume requires it.
- (decision) AD-6: Authentication = Cookie-based sessions (ASP.NET Core Identity). Simpler for single-user, no JWT refresh token complexity, httpOnly cookies more secure for this use case.
- (decision) AD-7: GeoIP lookup inline in the redirect controller (MaxMind GeoLite2 in-memory DB, <1ms lookups). AD-8: ORM = Entity Framework Core (clear entity relationships, migrations, LINQ).
- (event) Architecture spine + discussion doc drafted. 9 ADs locked via coaching path. Ready for review.
